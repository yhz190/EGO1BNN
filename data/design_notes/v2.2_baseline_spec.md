## 1.4 资源下降的"砍单触发阈值"（T6 的安全垫）

实测（D12）若 LUT 超过阈值，按序砍：

| 触发阈值 | 动作 | 省 LUT |
|---|---|---|
| >4,700 | ① 文本层字符从 40 → 24 个 | ~40 |
| >4,800 | ② VGA 12bit 色 → 4bit（只留 4 根 IO） | ~20 |
| >4,900 | ③ 7× 放大 → 6×（384×384） | ~20 |
| >5,000 | **视为设计缺陷，停线整改**（不允许靠砍功能过关） | — |

> **W1 执行口径（D12 实测后）**：上界 4,900 距停线 ≤5,000 只有 **100 LUT**，因此 D12 实测一旦落在 **4,800~5,000** 区间，就必须按 ①→②→③ 顺序严格裁剪，并把这三种裁剪视为**已批准的降级**（不需要重新评审）；只有 **>5,000** 才算设计缺陷。反过来说，若实测 ≤4,700，则视为资源健康，不再做任何裁剪。

# 3. 时钟、复位与内存映射

## 3.1 时钟

| 时钟 | 来源 | 频率 | 用途 |
|---|---|---|---|
| `clk_100m` | 板载晶振 P17 | 100 MHz | 寄存器二分频+BUFG 输入 |
| **`clk_sys`** | MMCM CLKOUT0（100/2，历史方案） | **50 MHz** | **全部核心逻辑** |
| 像素节拍 | `clk_sys` + 像素使能（÷2） | 25 MHz 等效 | VGA |
| 〔可选〕`clk_cam` | MMCM CLKOUT1（100×6/25，历史方案，未采用） | 24 MHz | OV7670 XCLK |

- **核心为单一时钟域**，VGA 用使能驱动 → 不需要 `set_clock_groups`、不需要跨域复位；
- 刷新率 25.000 MHz /(800×525) = **59.52 Hz**（官方 demo 已验证该板可显示）；
- **摄像头是唯一可选的 CDC 孤岛**（PCLK 域写、`clk_sys` 域读：2 级同步器 + 格雷码写指针），仅在启用档 3 时存在。
- 约束：`create_clock -period 10.000 [get_ports sys_clk_in]`（见 `board_ego1_soc.xdc`）。

## 3.2 复位

`sys_rst_n`（P15，低有效）→ 2 级同步器 → `rst_n`；异步复位、同步释放。

## 3.3 内存映射

| 区域 | 基址 | 大小 | 实现 | 访问者 |
|---|---|---|---|---|
| `IMEM/DMEM` | `0x0000_0000` | 8 KB | 2 × RAMB36 | CPU |
| `SFR` | `0x0001_0000` | 64 B | 寄存器 | CPU / 外设 |
| `WBRAM` 权重/阈值/CRC | `0x0002_0000` | 1 KB | 1 × RAMB18 | CPU 读（校验）、引擎读 |
| `FRAME` 输入双缓冲 | `0x0003_0000` | 1 KB | 1 × RAMB18 | 写：uart / CPU；读：引擎、VGA |
| `GALLERY` 预置图库 | `0x0004_0000` | 4 KB | 1 × RAMB36 | CPU 读（选图→FRAME） |
| `ACT_A` / `ACT_B` | `0x0005_0000` / `0x0005_1000` | 各 4 KB | 2 × RAMB36 | **仅引擎** |

**BRAM 合计**：5 × RAMB36 + 2 × RAMB18（=1 当量）= **6.0 块当量 = 12%**。
**字模 ROM 用分布式 ROM（640 B ≈ 80 LUT），不占 BRAM。**

> T6 判据与本节同口径：`RAMB36 ≤5 且 RAMB18 ≤2`。

## 3.4 SFR 寄存器表

| 偏移 | 名称 | R/W | 说明 |
|---|---|---|---|
| `0x00` | `CTRL` | W | bit0 自检；bit1 清结果；bit2 选图库回放 |
| `0x04` | `STATUS` | R | bit0 busy, bit1 done, bit2 err, bit3 frame_ready, bit4 crc_err, bit5 no_frame |
| `0x08` | `THRESH` | W | 二值化阈值 0~255（默认取 DIP 开关） |
| `0x0C` | `CLASS` | **R/W** | 固件写；类编码见 `src/weights_layout_spec.md` §9（**单一事实源，本文不复述数字**） |
| `0x10`~`0x18` | `SCORE0..2` | R | 三类得分（0~255） |
| `0x1C` | `FPS` | R | 板端帧计数（1 s 窗口） |
| `0x20` | `FRAME_SEQ` | R | 帧序号（查丢帧） |
| `0x24` | `MODEL_ID` | R | 模型版本号 |
| `0x28` | `MARGIN` | R/W | **UNKNOWN 的 margin 阈值（默认 24，DIP 可调）** |
| `0x2C` | `ERRORS` | R | CRC 错误计数 |
| `0x30` | `SCORE3` | R | **junk 类得分（0~255）**，VGA/固件读（不入结果帧） |

## 4.2 启动流程（**权重唯一加载路径**）

```

  → 主循环
```

## 4.3 固件骨架

```c
// sw/main.c —— 5 层整网，junk 第 4 类 + margin 双保险
int main(void) {
    uint32_t last_seq = 0;
    if (!selftest()) { STATUS_ERR(); for(;;); }      // WBRAM CRC16 + SFR 读写
    for (;;) {
        uint32_t st = STATUS;
        if (st & ST_FRAME_RDY) {
            uint32_t seq = SEQ;
            if (seq != last_seq) {
                last_seq = seq;
                THRESH = dip_threshold();            // 8 位 DIP → 阈值
                MARGIN = dip_margin();               // 高 4 位 → margin
                BNN_CONV(0, FRAME_BASE, WBRAM_BASE); // funct7=0 → 整网
                while (BNN_WAIT() & ST_BUSY) ;
                uint32_t s0=BNN_ACC0(), s1=BNN_ACC1(), s2=BNN_ACC2(), sj=BNN_ACC3();
                int cls = argmax4(s0,s1,s2,sj);
                // junk 类得分最高时 argmax4 已返回 3，无需再赋值
                else if (top1_minus_top2(s0,s1,s2) < MARGIN) cls = 3;  // 第二道闸
                CLASS = cls;
                uart_send_result(cls, s0,s1,s2, flags(st), FPS, seq);  // 10B
            }
        }
    }
}
```

# 5. Custom-0 指令集扩展

## 5.1 编码（custom-0 = `0x0B`）

| 指令 | opcode | funct3 | funct7 | rs1 | rs2 | rd | 语义 |
|---|---|---|---|---|---|---|---|
| `bnn.conv` | `0x0B` | `000` | **起始层 0~4** | 输入帧基址 | 权重基址 | — | 1 拍返回，不阻塞 |
| `bnn.wait` | `0x0B` | `001` | `0000000` | — | — | 状态字 | bit0 busy / bit1 done / bit2 err |
| `bnn.acc` | `0x0B` | `010` | **类别号 0~3** | — | — | 得分 | 0~255（**3 = junk 类**） |

**C 封装（必须 `volatile` + `"memory"`，否则 `-O2` 下会被优化/重排——这是证据链最脆的一环）**：

```c
#define BNN_CONV(layer, in, w) \
    asm volatile(".insn r 0x0B, 0, %0, x0, %1, %2" :: "i"(layer), "r"(in), "r"(w) : "memory")
static inline uint32_t BNN_WAIT(void){ uint32_t r; asm volatile(".insn r 0x0B, 1, 0, %0, x0, x0":"=r"(r)); return r; }
#define BNN_ACC0() ({uint32_t r; asm volatile(".insn r 0x0B, 2, 0, %0, x0, x0":"=r"(r)); r;})
#define BNN_ACC1() ({uint32_t r; asm volatile(".insn r 0x0B, 2, 1, %0, x0, x0":"=r"(r)); r;})
#define BNN_ACC2() ({uint32_t r; asm volatile(".insn r 0x0B, 2, 2, %0, x0, x0":"=r"(r)); r;})
#define BNN_ACC3() ({uint32_t r; asm volatile(".insn r 0x0B, 2, 3, %0, x0, x0":"=r"(r)); r;})
```

**funct7 语义（P1-5 闭环）**：`0` = 从 L1 跑完整 5 层；`1~4` = **从第 N 层起跑**（前置层结果需已在 ACT 中）。
用途：T8 逐层比对、单层调试。`>4` → 置 err 且**立即 ready**（不挂死）。

## 5.2 PCPI 握手时序

```
拍    1     2     3
pcpi_valid ──┐
pcpi_insn     <32bit>
pcpi_wr   ────（conv：0）
pcpi_ready ───┘   ← 第 1 拍即返回，CPU 继续取指；引擎内部置 busy
```

`bnn.wait` / `bnn.acc`：2 拍返回（第 1 拍锁存，第 2 拍给 `pcpi_rd` + **`pcpi_wr=1`** + `pcpi_ready=1`）。

**错误处理铁律（P0-2 修复）**：

| 情况 | `pcpi_ready` | `pcpi_wr` | 其它 |
|---|---|---|---|
| 非法 funct3（非 0/1/2） | **1** | **0** | 置 `SFR.ERRORS++` |
| funct7 超出范围 | **1** | **0** | 置 err |
| 引擎 busy 时收到 conv | **1** | 0 | 忽略，`ERRORS++` |
| 地址越界 | **1** | 0 | 置 err |

> **绝不允许"不拉 ready 按 NOP 处理"**——若 PicoRV32 语义是"等 ready"，CPU 会永久 stall。

## 5.3 引擎唯一启动路径

`bnn.conv` 是引擎**唯一**启动入口。UART/按键/拨码只能准备数据或置标志，不得直接触发。这是 RISC-V 赛道"指令真的在驱动硬件"的硬证据。

## 5.4 反汇编（修正后的真实编码）

按 `.insn r opcode, funct3, funct7, rd, rs1, rs2` 与 custom-0 = `0x0B` 重算（opcode 已核对）：

| 指令形态 | 机器码 | 字段 |
|---|---|---|
| `bnn.conv x0, a0, a1, L0` | **`0x00B5000B`** | f3=0, f7=0, rd=x0(0), rs1=a0(10), rs2=a1(11), op=0x0B |
| `bnn.wait a0` | **`0x0000150B`** | f3=1, rd=a0(10), op=0x0B |
| `bnn.acc a0, 0` | **`0x0000250B`** | f3=2, f7=0 |
| `bnn.acc a0, 1` | **`0x0200250B`** | f3=2, f7=1 |
| `bnn.acc a0, 2` | **`0x0400250B`** | f3=2, f7=2 |

# 6. BNN 计算引擎（核心）

## 6.1 网络定义（**5 层**，含每层二值化阈值）

| 层 | 输入 | 运算 | 累加范围 | 阈值 | 输出 |
|---|---|---|---|---|---|
| **L1** Conv1 | 64×64×1bit（FRAME） | 3×3, 1→8ch, XNOR+popcount9 | 0~9（4bit） | θ1 | 8 平面 × 64×64 bit → **ACT_A** |
| **L2** DWConv | ACT_A 8 平面 | 3×3 depthwise, 8→8 | 0~9（4bit） | θ2 | 8 平面 → **ACT_B** |
| **L3** Conv3 | ACT_B 8 平面 | 1×1, 8→**8**, popcount8 | 0~8（4bit） | θ3 | **8 平面** × 64×64 bit（32Kbit）→ **ACT_A[7:0]** |
| **L4** Pool | ACT_A[7:0] | **4×4** 块内计数，**≥8/16** 判 1 | 0~16（5bit；θ4 取 7bit） | θ4 | **8 平面 × 16×16 = 2,048 bit → LUTRAM** |
| **L5** FC | 2,048 bit | 2,048→4（3 类 + junk）, XNOR+popcount, **Q6 定点偏置** | 0~2,048（12bit） | — | 4 个得分（**19bit 有符号**） |

- **每层"累加 → 阈值比较 → 1bit"** 是标准 BNN 做法；若把累加值直接池化相乘，位宽会炸到 24 bit 且失去 XNOR 语义。
- **最大累加 9 bit → 统一 12 bit 累加器**，无溢出。
- **junk 第 4 类**（v2.1 新增）：训练时加"空背景/侧手/半手/遮挡"类，FC 从 3 类扩到 4 类；v2.2-patch2 起特征 1,024 → **2,048 bit**，FC 权重 4,096 → **8,192 bit**（见 §6.5）。

## 6.2 数据通路

```
   权重（WBRAM 按层基址）
        ▼
3×65bit 行缓冲 ─► 9bit 固定窗口 ─► 72 路 XNOR ─► 8×popcount9 ─► 8×12bit 累加
 （移位寄存器）      （导线）      （8ch×9tap）    （每通道 4bit）        │
                                                                       ▼
                                                     与 θ 比较 → 写激活 BRAM（1bit）
```

- ⛔ **行缓冲必须是"移位寄存器 + 固定抽头"**；写成"BRAM + 可变读指针"要 9×8 个 64:1 mux ≈ 1,500 LUT（差 25 倍）。
- 每周期输出 **1 个像素的全部 8 通道** = 72 MAC/周期。
- **L4 实现**：8 个通道计数器并行，按 **4×4** 块扫描（块内 ≥8/16 判 1；+180 LUT，见 §2.2），**不做 256 路并行**（那要 600~800 LUT）。
- **SAME padding（v2.2-patch1 定死）**：显式补 **1 列 + 1 行**；填充值统一为 **bit 0**——在 L1 的 0/1 域即 0，在 L2/L3 的 ±1 域即 −1（bit 0 ≡ −1）。**两域 pad 同为 bit 0，因此不需要任何 padding mux / 边界选择逻辑**（这正是方案 A 的结构性红利）。

## 6.3 层序列器 FSM

| 状态 | 动作 | 拍数 |
|---|---|---|
| `S_IDLE` | 等 `bnn.conv`；锁存 `start_layer`/rs1/rs2 | — |
| `S_L1` | L1：FRAME→ACT_A，逐像素（65×65 含补边） | **4,228**（4,225 扫描 + 3 拍外壳） |
| `S_L1_DONE` | **L1→L2 显式屏障**（实测 1 拍；保证 ACT_A 写完再读） | **1** |
| `S_L2` | L2：ACT_A→ACT_B（65×65 含补边） | **4,228**（4,225 扫描 + 3 拍外壳） |
| `S_L3` | L3：ACT_B→ACT_A[7:0]（**1×1 平面混合卷积，无 3×3 窗口 → 不加补边拍**；8 输出通道并行） | **4,098**（4,096 + 2 外壳） |
| `S_L4` | L4：4×4 块内计数 ≥8/16（8 通道并行）→ LUTRAM | **4,098**（4,096 + 2 外壳） |
| `S_L5` | L5：**每拍 8 特征 ×4 类**（复用 8 lane；feat 2,048 → 256 拍）+ 1 拍输出寄存 | **257** |
| `S_DONE` | 置 done，通知 SFR | 1 |
| 小计 | | **16,911** |
| 层间同步/地址/冗余 | **实测已含在各层"外壳"拍内**（RTL 无额外预留） | 0 |
| **总计** | | **16,911 拍 = 338.2 µs = 2,957 fps**（50 MHz，引擎独占） |

> 2,957 fps 是**引擎算力峰值**（8 通道、含 8 通道 L3/L4 并行扩展）；系统端到端受输入通道限制（UART 178 fps / 摄像头 30 fps）。

## 6.4 存储与 ping-pong（修正 R9/R10）

| 阶段 | 读 | 写 |
|---|---|---|
| L1 | **FRAME** | ACT_A[7:0] |
| L2 | ACT_A[7:0] | ACT_B[7:0] |
| L3 | ACT_B[7:0] | ACT_A[7:0]（8 输出通道占满 ACT_A） |
| L4 | ACT_A[7:0] | LUTRAM（2,048 bit） |
| L5 | LUTRAM | 结果寄存器 |

> L3 输出 32Kbit 占满 ACT_A 的 8 平面（仍**零额外 BRAM**）；L4 的 2,048 bit 用 LUTRAM 合理。

**FRAME 读口仲裁（N3）**：FRAME 只有 1×RAMB18（写口归 uart/CPU，**读口由引擎与 VGA 共用**）。
仲裁策略：**引擎绝对优先**；VGA 用 **64 bit 行缓存**——每条源行在 7 次重复显示期间分时读入 64 次，
冲突时让 1 拍。整帧 VGA 仅占约 **4.4k 拍**（占引擎 19k 拍的 23%），引擎等效 23.6k 拍 ≈ 472 µs，
仍 **2,100 fps 以上**，对 30 fps 判据无影响。

> **W2 两个帧率的口径（答辩统一说法）**：
> **2,957 fps** = 引擎**独占** FRAME 读口、不计 VGA 分时的**理论峰值**（16,911 拍 @50MHz，8 通道）；
> **≈2,100 fps** = 引擎与 VGA **共享** FRAME 读口、计入 VGA 行缓存分时后的**等效帧率**（23.6k 拍 ≈ 472 µs）。
> 验收 T4a 用的是**板端实测帧计数**，两者都远高于 30 fps 判据；答辩时先报 2,100（保守、含争用），被追问峰值再报 2,957。

| 缓冲 | 大小 | 实现 |
|---|---|---|
| IMEM/DMEM | 8 KB | 2 × RAMB36 |
| WBRAM | **2 KB 逻辑地址空间**（8,648 bit = 1,081 B） | 仍 **1 × RAMB18**（18 Kbit 物理占 47%） |（口径A：bit 直除 8,648/8=1,081 B）
| FRAME[2] | 1 KB | 1 × RAMB18 |
| GALLERY（8 帧） | 4 KB | 1 × RAMB36 |
| ACT_A / ACT_B | 各 4 KB | 2 × RAMB36 |
| **合计** | | **6.0 块当量 = 12%**（若综合因地址映射拆成 2 实例则为 6.5，以综合报告为准） |

## 6.5 权重表格式（`weights.hex`，**8,648 bit = 271 字 = 1,084 B**）（口径B：32-bit 字对齐 271×4=1,084 B；两口径并存，勿互算）

> v2.2-patch2：L3 4→8 通道、FC 特征 1,024→2,048、θFC 改 **Q6 定点（4×16bit）**。
> 4 通道旧版（4,476 ~ 4,448 bit）归档为历史附录，正文只保留 8 通道口径（单一事实源）。

| 偏移(bit) | 字段 | 位数 |
|---|---|---|
| 0 | L1 权重（8ch × 3×3） | 72 |
| 72 | L2 权重（8ch × 3×3，depthwise） | 72 |
| 144 | L3 权重（8out × 8in） | 64 |
| 208 | L5/FC 权重（**4cls × 2,048**） | **8,192** |
| 8,400 | θ1（8ch × 4b） | 32 |
| 8,432 | θ2（8ch × 4b） | 32 |
| 8,464 | θ3（8out × 4b） | 32 |
| 8,496 | θ4（8ch × 7b） | 56 |
| 8,552 | **θFC（4cls × 16b，Q6 有符号）** | 64 |
| 8,616 | MODEL_ID | 16 |
| 8,632 | **CRC16**（poly 0x1021 / init 0xFFFF，覆盖前面全部字段） | 16 |
| **合计** | | **8,648 bit → 271 字（对齐 8,672 bit = 1,084 B）** |（口径B：32-bit 字对齐 271×4=1,084 B；两口径并存，勿互算）

## 6.6 状态与边界

| 情况 | 行为 |
|---|---|
| busy 时再收 conv | 忽略 + `ERRORS++`，**照常 ready** |
| 帧未就绪就推理 | 照算，置 `no_frame` |
| junk 类得分最高 | 输出 UNKNOWN |
| 三类 top1-top2 < MARGIN | 输出 UNKNOWN（第二道闸） |
| 阈值 > 累加最大值 | 该层全 0 → 下游全 UNKNOWN（可诊断） |

## 6.7 为什么**不采纳**"GAP + 1×1 Conv 替换 FC"（docx 建议）

| 项 | docx 主张 | 核算 |
|---|---|---|
| 前提①"FC 占 81% 权重 → PV 瓶颈" | 称 WBRAM 装不下 | **8,648 bit（FC 8,192 bit = 94.7%）≪ RAMB18 的 18 Kbit**，占 47%，前提不成立 |
| 前提②"FC 导致 BRAM 紧张" | 称需频繁外部加载 | 权重全在片上 RAMB18，**无外部加载** |
| 方案：GAP 4 通道 → 1×1 4→3 | 参数 12 个 | 丢失全部空间信息；3 类手势靠 4 个全局均值分类，**准确率会崩到接近随机（≈33%）** |
| 收益：权重降 1~2 个数量级 | 真 | 但收益对象是个本来就只占 15% 的 1KB 缓冲——**收益为零** |

**结论**：FC（256→4，1,024 bit）是本网络的合理选择，与 BNN 文献（XNOR-Net/DoReFa 在小特征图上用 FC）一致。**该建议拒绝，理由记录在案**（候选≥3 的要求也由此满足：FC / GAP+1×1 / 全局池化+FC 三种方案已评估）。

| flags | 1 | bit0 done / bit1 busy / bit2 crc_err |
| fps | 1 | 板端帧计数 |
| seq | 1 | 帧序号 |
| CRC8 | 1 | 多项式 `0x07` |

> junk 得分 `sj` **不占结果帧**（省带宽），由 `SFR.SCORE3` 提供，VGA 与固件读取。

**灰度帧（4,101 B，仅调试档）**：命令 `0x11`，载荷 4,096 B 灰度。
板上**不设 4KB 缓冲**：`uart_bridge` 边收边比较 `THRESH`，每 8 字节打包成 1 字节直接写 FRAME（**流式二值化，+30 LUT**）。

**CRC 失败行为（P3-3）**：`ERRORS++`、STATUS 置 `crc_err`、**不写 FRAME、不翻 frame_valid**。

## 7.2 档 1：PC 串口注入（地基，D2）

- 波特率 **921600**；**USB 桥实测为 FTDI FT2232（双通道：A=JTAG，B=UART），上限 ≥3 Mbps → 921600 在安全区**（原文档的"CP2102"来自 PDF 手册，已被实测推翻）；
- 二值帧：517 B × 10 bit / 921600 = **5.61 ms → 178 fps**；
- 灰度帧：4,101 B → **≈22 fps < 30 fps 判据** → **仅供调试，30fps 判据只对二值帧路径生效**；
- 双缓冲 + `frame_valid` 翻转防撕裂。

## 7.3 档 2：BRAM 预置图库（零 PC 兜底）

综合期 `$readmemh` 8 张代表帧；拨码 SW[2:0] 选图 → 按键触发 → 拷到 FRAME → 正常推理。**不经串口即可跑满 30 fps。**

## 7.4 档 3：OV7670（**stretch goal**，D19 前全绿才启动）

| 项 | 设计 |
|---|---|
| 接口 | DVP 8bit + PCLK/VSYNC/HREF + XCLK + SCCB，接 **J5** |
| XCLK | **MMCM CLKOUT1 = 24 MHz（100×6/25，历史方案，未采用）**；PCLK 作为独立时钟岛 |

# 9. 零 DSP 保证体系

## 9.1 三层防护

| 层 | 措施 |
|---|---|
| 写法 | ① 常量乘法改移位/加法 ② 地址计算禁 `a*b` ③ 顶层 `(* use_dsp = "no" *)` ④ **PicoRV32 禁 `ENABLE_FAST_MUL`** |
| 闸门 | 综合后 + 布线后双检查（§9.2） |
| 反证 | DSP 版对照实验（§9.3，D9 前完成） |

## 9.2 构建闸门（**两级**，P2-2 修复）

```tcl
# ① 综合后
set n_dsp [llength [get_cells -hier -quiet -filter {REF_NAME =~ DSP48*}]]
if {$n_dsp != 0} { error "❌ 综合后 DSP 闸门失败：$n_dsp" }

# ② 布线后（opt_design/place/route 之后，write_bitstream 之前）
set n_dsp [llength [get_cells -hier -quiet -filter {REF_NAME =~ DSP48*}]]
if {$n_dsp != 0} { error "❌ 布线后 DSP 闸门失败：$n_dsp" }
set wns [get_property SLACK [get_timing_paths -delay_type max]]
if {$wns < 0} { error "❌ 时序闸门失败：WNS=$wns" }
report_utilization   -file reports/util.rpt
report_timing_summary -file reports/timing.rpt
puts "✅ 双闸门通过：DSP=0, WNS=$wns"
```

## 9.3 DSP 对照实验（**修正口径**，P3-1/R21）

本文档数据通路是 **8 通道 × 9 位 = 72 位/拍**（不是 512 位/拍）：

| 实现 | 每通道做法 | DSP | LUT（口径：仅 XNOR+计数+累加） |
|---|---|---|---|
| **A. LUT popcount（采用）** | 72 XNOR(72) + 8×popcount9(~80) + 8×12bit 累加(~40) | **0** | **~192** |
| B. DSP popcount（对照） | 72 XNOR(72) + 每通道 1 个 DSP（`×全1` 即 popcount9）+ PCIN 级联累加 | **8** | **~92** |

**诚实结论**：DSP 版省约 **100 LUT（0.5% 器件）**，代价 8 个 DSP（8.9%）。
所以"零 DSP"**不是**唯一可行路线，其真实价值是：
1. **资源类型与算法本质对齐**——BNN 的核心是"数位与 + 计数"，用 DSP 只用到它的"×全 1"，浪费 25×18 乘法能力；
2. **可移植性**——可落到无 DSP 器件（CPLD / 低端 FPGA）或移植 ASIC；
3. **消除隐式推断风险**——DSP 版依赖工具正确推断，LUT 版行为完全确定；
4. 8 个 DSP 的节省在本器件上不影响任何指标，**但这 8 个是扩展/移植时的稀缺资源**。

> v2.0 的"32 DSP / 900 LUT / 32 通道撞 90 上限"作废（那是按 512 位/拍估的，与本架构不符）。答辩一律用本表。

### 9.4 扩展路线图（回答"so what"，N7 修复）

| 规模 | LUT 版（0 DSP） | DSP 版（每通道 1 DSP） | 真正的瓶颈 |
|---|---|---|---|
| 8ch（本项目） | ~192 LUT 数据通路 | 8 DSP（8.9%）+ ~92 LUT | **输入帧率与准确率** |
| 32ch | ~770 LUT 数据通路 | 32 DSP（36%）+ ~370 LUT | BRAM（激活 4×）与训练数据 |
| ~90ch | ~2,160 LUT | **90 DSP 用满 → DSP 版无法再扩** | LUT 仍只占 ~10% |

**诚实结论**：DSP 的上限出现在约 90 通道，不是 32 通道——v2.0 的"32 通道撞墙"已作废。
本设计选零 DSP 的理由是**资源类型对齐 + 可移植性 + 行为确定**（§9.3），不是"扩展唯一路径"；
真正的扩展瓶颈是 **BRAM 与数据/准确率**，与 DSP 无关。

# 10. 算法与模型

## 10.1 训练流程

```
数据集：RPS/LeapGestRecog + 设备实拍补采（**含 junk 第 4 类**）
  → 【第 0 步】ROI 中心裁剪 + 归一化（v2.1 提升为标准步骤）
  → resize 64×64 → 灰度
  → 自适应阈值二值化（与板端同一函数 preprocess.py）
  → PyTorch BNN（1bit 权重+激活，STE）
  → 逐层统计 θ1~θ3（使该层输出与浮点参考误差最小的分位点）
  → 导出 weights.hex（**8,648 bit** = 271 字 + CRC16）
  → golden model 复算，与导出值位精确比对
```

## 10.2 数据采集制度（v2.1 新增，11-6-2）

- **D3 引擎一打通就开始采**，不等风险触发；
- 规模：**每类 ≥200 帧**，覆盖 **3 种光照 × 2 种手位**；junk 类 ≥150 帧；
- 采集脚本 = 训练脚本（同一份 `preprocess.py`）→ 从根上消除域偏移；
- 采集走档 1（PC 注入），零硬件成本。

## 10.3 拒识策略（v2.1 升级，11-6-1）

| 道 | 机制 | 说明 |
|---|---|---|
| 第 1 道 | **junk 第 4 类**（FC 输出 4 类） | 异分布输入由模型自己判为 junk，比分数空间阈值稳 |
| 第 2 道 | margin：`top1-top2 < MARGIN` → UNKNOWN | 三类置信度接近时兜底 |
| 可视化 | VGA margin 条 | 答辩可展示"拒识过程" |

## 10.4 降级路线

① 判据下调至 80%（已写入 T1b 条件）→ ② 扩数据至每类 500 帧 → ③ 退 2 分类 → ④ 退模板匹配（仍是 XNOR+popcount）。
