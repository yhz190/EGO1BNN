# T4b 正测记录：预打包流式注入（2026-11-01）

> 判据：注入回环 **≥150 fps**（v2.2 §1.3 原文，**不改判据**）
> 方法：离线预打包 620 帧 → 连续流式写串口 → 首字节到末字节墙钟计时。**RTL 零改动**。
> 结论：**PASS — 180.56 fps（理论 178.3），且 620/620 结果帧 cls 与模型一致。**

## 1. 为什么 T4a 与 T4b 不是一件事

| | T4a（端到端） | T4b（注入回环） |
|---|---|---|
| 测什么 | 含上位机逐帧预处理/打包/停等 + 板端推理 + 回帧 | **注入通道本身极限** |
| 方法 | 停等协议，逐帧等结果帧 | 预打包、连续写、不逐帧等 |
| 实测 | **59.55 fps**（16.8 ms/帧） | **180.56 fps**（5.5 ms/帧） |
| 判据 | ≥30 fps ✅ | ≥150 fps ✅ |

> 16.8 ms/帧 中，UART 传输只占 ~5.6 ms，其余 ~11 ms 是 PC 端逐帧处理与停等开销——
> 拿端到端数字去套 T4b 判据，等于用停等协议的测量伪影迁就判据。**两者各归各的口径**。

## 2. 实测数据

```
port=<COM_PORT> baud=921600 frames=620  bytes=320540 (517.0 B/frame)
theoretical: 3.48 s -> 178.3 fps @921600 baud (10 bit/byte)
streamed 320540 bytes in 3.434 s  ->  180.56 fps  (0.09 MB/s)
rx result bytes: 6200 (expect ~6200)
T4b criterion (>=150 fps): PASS
decoded result frames: 620
cls match with model: 620/620
T4b incl. correctness: PASS
```

- 320,540 B = 620 × 517 B（A5 10 len payload CRC8）
- 3.434 s → **180.56 fps**（略高于"理论 178.3"，因 921600 实际波特与理论值有 ±0.1% 偏差）
- 板上 **ping-pong 双缓冲连续收**：620 帧全部处理，回帧 6,200 B 全收到（=620×10 B），无丢帧
- 结果帧逐条解码 CRC 全过，`cls` 与 Q6 模型 **620/620 一致**

## 3. 关键条件（少一个就测不出来）

1. **预打包**：离线把 620 帧组帧成单块 320 KB bytearray（无实时处理）；
2. **大块写**：`serial.write()` 每次 ≥8 KB（小包写会被 USB 调度吃掉）；
3. **不逐帧等**：后台线程只做 drain/收集，主循环连续写；
4. PC 端 **FTDI 的 latency timer 未改**（16 ms 默认），写入不受延迟定时器限制，无需改驱动。
   > 注：评审提到的 CP2102 不适用于本板（EGO1 是 FT2232H）；若将来换 CP2102 需把 latency 调到 1 ms。
